# bundle example

The same buildless sources as the other demos, **folded per entry point** by the build pipeline's `bundle` stage:
`app.js` keeps its exact URL with `lit` inlined, the dynamically-imported module lands in content-hashed `chunks/`, and no import map ships at all.

```sh
cd examples/bundle
cargo run --features full --bin web-modules -- build   # every knob comes from package.json's web_modules block
python3 -m http.server -d dist
# open http://localhost:8000/
```

## What it demonstrates

- **Manifest-driven config**: the `web_modules` block in [`package.json`](package.json) is the whole CLI configuration (`roots`, `out`, `minify`, `sourcemap`, `packages`, `bundle.entries`), read from the directory `web-modules build` runs in; the invocation takes no flags.
- **The entry keeps its URL**: [`web/index.html`](web/index.html) is a literal static page loading `./app.js`, before and after bundling; existing HTML never changes.
- **A real split point**: [`web/app.ts`](web/app.ts) reaches [`web/lazy.ts`](web/lazy.ts) through a dynamic `import("./lazy.js")`, so the bundle stage emits a content-hashed chunk that the browser fetches on the first click only.
- **One pass for the policies**: `minify` and `sourcemap` apply through rolldown's own codegen; `dist/app.js` is minified, linked to `app.js.map`, and each chunk carries its own map.
- **Comments under bundling**: legal comments (`lit`'s `@license` headers, the banner in `app.ts`) stay inline in the bundle; `collect` has no link mode here, which is why the manifest sets no `comments` key.

## Notes

- Building from this checkout uses `--features full`, the same set the released `web-modules` binary is built with: `bundle` is part of `full` but not of the default features (rolldown is heavy), and `lean` is the rolldown-free aggregate.
- Bundled builds re-vendor from the network on every run, since the vendored tree is consumed by the bundler rather than kept as a cache.
- For the buildless counterpart of this page (import map, vendored `web_modules/` tree, Tera template) see [`gh-pages`](../gh-pages).

`dist/` is generated by the build and gitignored.
